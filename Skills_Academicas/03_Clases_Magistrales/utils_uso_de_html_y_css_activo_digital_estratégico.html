01 Estructura Completada

Preparación del Entorno y Archivo Principal

Todo equipo informático convencional dispone ya de la infraestructura elemental para iniciar un activo web propio sin necesidad de contratar software especializado. En el flujo documentado, el punto de partida consiste en crear una carpeta dedicada en el ordenador (denominada en el ejemplo página web o mi página web) y generar dentro un documento de texto plano mediante clic derecho → Nuevo → Documento de texto.

Conversión de extensión e interpretación del navegador

Para que el sistema operativo y el navegador reconozcan el archivo como página web, es imprescindible activar en el explorador la opción Vista → Extensiones de nombre de archivo, lo que revela la terminación .txt y permite renombrar el fichero a index.html. Al confirmar el cambio de extensión, el navegador pasa a abrir el documento con doble clic porque HTML es el lenguaje que interpreta directamente.

Asimismo, haciendo clic derecho dentro de la página abierta en el navegador y seleccionando Ver código fuente de la página, cualquier responsable o estudiante puede auditar en tiempo real las instrucciones HTML inmersas en el documento.

Editor en fuente Disponibilidad Valor operativo
Bloc de notas Ya instalado en Windows Funcional para ediciones iniciales; incómodo porque no colorea ni renderiza las etiquetas.
Sublime Text Descargable en sublimetext.com (coste: no consta) Colorea cada etiqueta HTML; si falta un símbolo de cierre >, el código inferior deja de colorearse y delata el fallo al instante.
Visual Studio Code Instalación rápida (tarifa/licencia: no consta) Permite abrir la carpeta completa (File → Open Folder), gestionar múltiples archivos en el panel lateral y acelerar el desarrollo del sitio.

02 Estructura Completada

Estructura Arquitectónica en HTML

Los elementos en HTML se articulan mediante una arquitectura explícita: una etiqueta de apertura, un contenido y una etiqueta de cierre. El esqueleto arranca con la declaración <!DOCTYPE html> para indicar al navegador el tipo de documento, seguida de la etiqueta principal <html>, que encapsula todo el árbol de etiquetas.

Jerarquía de documento, buenas prácticas y medios básicos

Dentro de <html> conviven dos bloques diferenciados: el encabezado técnico <head> —donde reside <title> para definir el texto de la pestaña del navegador— y el cuerpo <body>, único ámbito cuyo contenido (títulos, párrafos, imágenes, vídeos y enlaces) se muestra visualmente en pantalla.

Para la jerarquía textual se emplean encabezados desde <h1> (máxima relevancia y tamaño) hasta <h6> (mínima jerarquía), junto con párrafos <p>. Existen también etiquetas vacías sin contenido interno ni etiqueta de cierre, como <br>, destinadas a ejecutar una acción concreta como el salto de línea.

Reglas de rigor señaladas en la fuente: aunque el navegador tolera ciertas omisiones de cierre en páginas elementales y no distingue entre mayúsculas y minúsculas (<P> y <p> funcionan), el estándar recomienda escribir todas las etiquetas en minúsculas y cerrarlas siempre para evitar «errores extraños» cuando conviven imágenes, enlaces, vídeos y estilos.

La inserción de imágenes con <img> admite rutas locales en carpeta dedicada (img/imagen1.jpg) o direcciones externas completas; la fuente advierte que las rutas externas dejan de verse si el servidor de origen retira el archivo. Se acompaña de width y height (ejemplo citado: 300 por 200) y del atributo descriptivo alt. Para la navegación se emplea <a href="...">, opcionalmente con atributo target en valor _blank (nueva pestaña) y title="..." (descripción emergente tipo tooltip).

03 Estructura Completada

Navegación y Contenidos Estructurados

El salto desde una página aislada hacia un portal corporativo o académico completo se produce al adoptar etiquetas semánticas de distribución y una arquitectura multipágina coherente. El proyecto modelo desarrollado en la fuente —un sitio sobre Tecnología y Gadgets— organiza cada pantalla en tres grandes bloques dentro de <body>:

Bloque semántico Función en el sitio Etiquetas asociadas
<header> Cabecera del portal con el título principal y el menú de navegación. <h1>, <nav>, <ul>, <li>, <a>
<main> Contenido diferencial y central de cada sección (bienvenida, tablas, vídeos, formulario). <h2>, <p>, módulos específicos
<footer> Banda inferior para información institucional o aviso legal («Todos los derechos reservados»). <p>

Arquitectura de 5 páginas interconectadas: manteniendo el mismo encabezado y pie en todas ellas y variando únicamente el interior de <main>, se crean cinco ficheros en la raíz: index.html (página de inicio, con el logotipo de la carpeta img/), reviews.html, comparativas.html, tutoriales.html y contacto.html. La fuente recalca una regla crítica de integridad: los nombres escritos en el atributo href deben coincidir exactamente con los nombres reales de los ficheros en la carpeta; de lo contrario, el enlace falla.

04 Estilo Completada

Diseño y Estilos Visuales con CSS

La eficiencia operativa de una plataforma web radica en separar el contenido (HTML) de la presentación visual (CSS). Aunque es posible incrustar estilos internos mediante la etiqueta <style> dentro de un HTML, la fuente subraya que dichos estilos no son reutilizables. La solución estandarizada consiste en crear la carpeta css/ con el fichero style.css y vincularlo mediante <link rel="stylesheet" href="css/style.css"> en el <head> de cada una de las páginas del sitio.

Sistema visual centralizado, Flexbox y CSS Grid

  • Base tipográfica y fondos: en body se fijan la familia tipográfica, color de fondo (background-color), color de texto y eliminación de márgenes predeterminados. Para imágenes de fondo se utiliza background-image: url(...) combinada con background-repeat: no-repeat, background-position: center y background-size: cover.
  • Navegación e interactividad: eliminación de viñetas (list-style-type: none), disposición horizontal en línea con márgenes laterales, supresión de subrayados y pseudoclase :hover para cambiar de color al pasar el ratón.
  • Iconografía gratuita: inserción de iconos mediante Google Fonts Icons (fonts.google.com/icons), enlazando su hoja CSS en el <head> y añadiendo el código del icono a los ítems del menú (Inicio, Reviews, Comparativas, Tutoriales, Contacto).
  • Maquetación en Flexbox y CSS Grid: display: flex con gap: 20px organiza columnas paralelas (formulario y mapa en contacto.html); display: grid con grid-template-columns: repeat(3, 1fr), gap: 10px y max-width: 900px estructura las 4 tarjetas de producto de comparativas.html.
  • Botón flotante de contacto: enlace con clase .boton-flotante e icono PNG de WhatsApp fijado en la esquina inferior derecha mediante position: fixed, bottom: 20px, right: 20px, dimensiones 50px × 50px, border-radius: 50%, sombra y z-index: 100.

06 Despliegue Completada

Despliegue e Infraestructura Digital

Un activo digital desarrollado en local solo genera retorno organizativo cuando se vuelve accesible mediante una dirección web compartible. La fuente documenta la publicación abierta en Internet mediante GitHub (github.com) y GitHub Pages, permitiendo compartir el enlace operativo con clientes, dirección o profesorado sin contratar servidores dedicados. Nota de contexto de la fuente: en el ejemplo de publicación mostrado en vídeo se sube un proyecto previo maquetado con Bootstrap (secciones de catálogos, promociones y contacto), verificando que el mismo procedimiento rige para cualquier sitio HTML/CSS.

Flujo de publicación y control de versiones

Paso Acción en GitHub Requisito crítico
01 Registro y verificación en github.com (Sign up) Correo electrónico, contraseña, nombre de usuario, resolución de captcha y código de confirmación recibido por correo.
02 Creación del repositorio (Create repository) Nombre identificativo (ej. web-game-store-mi-primera), descripción y visibilidad marcada como Public.
03 Subida de ficheros (Upload existing files) y Commit Incluir obligatoriamente index.html como archivo raíz que busca GitHub, junto con la carpeta img/ y demás activos; documentar el envío en el mensaje de commit.
04 Activación en Settings → Pages En el apartado Branch, cambiar de None a la rama main, mantener la carpeta / (root) y pulsar Save.
05 Verificación de despliegue y obtención del enlace Esperar a que el estado del procesamiento en la pestaña Code cambie a verde y abrir la URL generada en Pages.

Transparencia documental: Límites de almacenamiento, ancho de banda mensual, dominio personalizado o tarifas de planes empresariales de GitHub: no consta en la fuente.
